Capability model

The Auction House module is not globally write-enabled. It combines broad read-only administration with narrowly scoped DSP/Topaz Test-environment executors. Live environments remain blocked.

Reading the Economy page

  • Window sets the time range for every number. Arrows and percentages compare it with the same-length period just before.
  • Market activity: daily bars; switch between Sales, New listings and Gil volume. Orange bars mark days with admin actions.
  • Supply history: the game server keeps no history of how much was listed, so the toolkit saves a snapshot once a day. A trend appears from the second day. Record now saves today's immediately (toolkit database only). Under the chart, baselines say whether each figure is Normal, Above usual or Below usual compared with its previous snapshots; they say "building" until 7 days exist.
  • Admin actions: seeds, restocks, Admin Buys, returns and rewards done through this toolkit, with the item's median sale price 7 days before and after. Other things change at the same time, so treat it as a pointer, not proof.
  • Price movers: items whose median sale price changed most. Items with very few sales are hidden unless you tick "include thin evidence" (shown with ⚠).
  • Where to look: Needs supply (selling but nearly nothing listed), Oversupplied, Stagnant (old listings, no sales) and Seller concentration (one seller holds most of the supply). Hover a card subtitle for its exact rule.

Seeding test data (Seeder tab)

The Seeder tab has a "Market history & scenarios" panel. It fills the Economy page with test sales and listings from 25 fake sellers (Tst*), so Clear only ever removes those rows. Choose Seed history, Add scenarios or Clear, press Preview, then type the profile name and Run. It needs the same write settings as every other test write (below).

Anomalies and character pickers

The Economy page Anomalies card flags items whose recent median sale price or sales volume departs from their own 60-day history, listings priced above 3x or below 0.4x the item median sale, and sellers posting far more than usual. Items with fewer than 5 earlier sales are never judged. In Restock and Inbox, pick characters by typing a name or ID, or use Browse; Restock spreads listings round-robin across every seller chosen, and can add a whole category (up to 50 items; price defaults to each item's average sale). This replaces the Seeder's category seeding.

Items and Sellers pages

Picking an item shows Recent sales (newest 50, scrollable) above every Active listing (no row cap). The Markup chip compares each asking price with the median of recent sales of the same type (single or stack): red above +50%, amber +15% to +50%, grey within ±15%, green below −15% (underpriced). Use the filter row to narrow by name, price range, type or markup; Buy all / Return all then act only on the filtered rows and say "(filtered)". Seller names jump to the Sellers tab and item names jump back to Items; ← Back returns where you came from.

A seller shows the same filters plus their last 30 days: items sold, gil earned, sell-through (sold ÷ sold + still listed) and median hours to sell, with their recent sales listed above their active listings. Seller listings carry the same Markup chip, measured against the median 30-day sale price of that item across all sellers (— if it has not sold in that window).

On the Economy page, the Supply history card shows four tiles — active listings, asking gil, sell-through and 7-day sales — each compared with the snapshot about 7 days earlier (sell-through in percentage points). With a shorter history the oldest snapshot is used and the span is stated; with one snapshot the tiles say they need a second.

Items status, Buyers, Cleanup and Presets

Items has a status toggle: Active (listed now), Unlisted (Auction House items with no active listing) and All. Unlisted and All load the full item catalog and add Sold and Avg sale columns, so you can browse everything that could be on the AH. Unlisted items can still be restocked from the item detail.

Buyers lists who bought what over 7, 30 or 90 days. Sold rows on this server record only the buyer's name, so buyers are matched by name. Open a buyer to see top items, top sellers and each purchase with its median sale price and markup; a purchase 50% or more above the median counts as overpaid. Refund sends the overpaid difference as gil to the buyer's delivery box through the same guarded rewards flow as Inbox (typed confirmation required). The sale itself is not reversed, and the buyer must have a character record on the server.

Buy as… on any listing row in Items or Sellers buys that listing for a chosen character: search the character, Preview, then confirm. The buyer must be offline with enough gil and a free Inventory slot.

Cleanup finds listings by seller (search by name or ID, including AH-only fake sellers), item, category, price range and minimum age, then Admin Buys or Returns them. An empty result shows how old your oldest active listing is, so you can lower the age rule. Presets stores reusable Restock and Cleanup rules; Restock falls back to the default seller (AHRestock, editable) when no character is chosen.

Arbitrage compares listings with NPC prices: Underpriced listings (asking below what an NPC pays), Post for profit (vendor-sold items worth more on the AH) and Vendor loops (an NPC sells an item for less than any NPC pays, a data exploit). “Clean up via Cleanup rules” loads the max vendor ratio rule so it can be previewed and run with a preset. Restock presets can also include or exclude specific items.

Synth & Crafting (sidebar, /synth) browses, checks, edits and ports the synth_recipes table on DSP, Topaz and LSB layouts. The Audit tab flags recipes whose ingredients have no vendor, guild shop, mob drop or craftable source in the data (gathered, fished and quest items show here too). Edits show the exact SQL for each server layout; applying needs the same Test write gate as the AH.

Write guardrails

DSP/Topaz Test writes require the existing Auction House Test-write feature flag, an active environment classified as Test, compatible discovered schema, and an exact typed confirmation equal to the active profile name. Preview-bound operations also revalidate live state immediately before mutation and use replay protection where applicable.

Global/general write readiness remains intentionally separate from these scoped executors. A green scoped Test status must never be interpreted as unrestricted write enablement.

Legacy MyISAM boundary

Historical DSP/Topaz databases may use MyISAM for character Inventory. MyISAM does not provide transactional rollback, so player-backed listing/purchase operations that require atomic Inventory/gil changes fail closed unless the relevant tables are transactional.

Other operations use safer contracts where possible: for example, Return can use Mog delivery when direct Inventory mutation is not rollback-safe.

Administration surfaces

Listings manages exact active rows. Seeder handles player-backed posting and synthetic supply. Cleanup previews rule-selected stale listings. Presets stores reusable cleanup/seed configuration only. Economy is read-only intelligence. Rewards delivers saved/ad-hoc bundles. Reward History tracks campaigns and failed-recipient retry previews. Activity consolidates execution outcomes, preview/replay evidence, and reward campaigns.

Intentional limitations

  • No unrestricted or Live write mode.
  • No automatic background cleanup or recurring mutation.
  • No augmented/custom reward-item extra payload generation until DSP/Topaz serialization is proven.
  • No fabricated audit history for mutations that occurred before execution-event recording was added.
  • LSB execution remains deferred until a runnable LSB Test environment exists.
