## Editor interaction design (no mutable implementation in this PR)

1. **Library → open/copy → design-only draft.** Guided mode shows plain-language purpose/rationale, Given/When/Then, ordered step cards, inputs, expected vs observed requirements, assertion/readback bindings, unknowns and missing proofs. Advanced mode edits the *same schema* with revision check and validation; no separate JSON dialect. In-scope now: design only, not a live editor.
2. **Parameter picking is a two-stage process.** Query existing catalog **read-only** → show source candidates with precise lineage, source path and identity status → require local source/client/zone reconciliation before enabling a confirmed binding. Ambiguity is a visible blocker; missing lookup source is *unavailable*, not empty or ID 0. Manual text cannot conjure a trusted ID.
3. **Steps and evidence.** Keep stable step IDs through reordering; link assertions to existing observation names, source:line+commit and evidence pointers. Show missing expected oracle as **UNKNOWN**, not PASS; preserve imported/recalculated verdicts separately from independently authenticated observations. No step is an instruction to invoke a GM or headless tool.
4. **Preflight.** Validate unknown IDs, missing provenance, stale source revision, unsupported operation/readback, duplicate identities, optional missing dataset, and mutating capability. Require explicit case-specific operator approval *outside this editor* before eventual state-changing execution. Design-only saves and previews may never grant it.
5. **Reverse flow later.** Import provenance-preserving observations → human-review draft candidate; do not backfill an expected normative oracle from what happened. Decoder confidence is distinct from server/client identity confidence.

## Safe isolated adapter slice

`scenario_authoring.catalog_adapter` calls *existing* `gm_commands.lookup` and `gm_commands.catalog_commands`, not routes and not command-preview / action code. It supports deliberately bounded DSP-only `item`, `keyitem`, `npc`, `mob`, `zone` and metadata-only `gm` discovery. It never generates an ID; outputs catalog candidate identities (including duplicate-ID ambiguity), a relative source path and explicit unreconciled status. Missing checkout/files raise an availability error, never return synthetic fallback rows. Every result has `execution_enabled=false`, `binding_verified=false`, `operator_review_required=true`. No root filesystem paths, raw scripts or GM invocation strings leave the adapter.

This is **not** the production picker API and does not replace Item Browser / Key Items / Entity Browser's cross-source reconciliation. A future UI route must be reviewed for auth, bounded queries, audit labeling and error handling before connecting it.
