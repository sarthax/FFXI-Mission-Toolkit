# R7 #1295 — Bounded persisted inventory v2 (draft)

Endpoint: `GET /api/supervisor/test-character-inventory-v2?charid=...&location=1&cursor=0&limit=100`.
Existing supervisor bearer token and disposable-character allowlist are mandatory. Location is restricted to 0 inventory, 1 Mog Safe and 10 Mog Safe 2. The dedicated supervisor DB principal must have SELECT-only privileges on **both `chars` and `char_inventory`**: the former distinguishes nonexistent characters from an authorized empty container. Do not assume either grant is deployed; verify effective privileges during local acceptance. DB connections target 127.0.0.1 and are read-only. The HTTP supervisor listener must be bound to loopback by deployment configuration; this route uses bearer authorization and does not independently establish an HTTP client-origin restriction.

Rows are ordered by slot, with itemId, quantity and opaque base64 extra bytes; absent extra differs from zero bytes. No augment or installed-furnishing flags are inferred: both are UNKNOWN/UNSUPPORTED until independently source-backed. Scope, UTC query timestamp, source kind and unauthenticated source-revision UNKNOWN are explicit. No claims of runtime memory or client agreement.

`total_rows`, `row_count`, `has_more`, `next_cursor`, `truncated` and `complete` describe only one scoped SELECT transaction. A page with offset > 0 is never marked a complete snapshot. Each HTTP call is an independent transaction: pages cannot be combined into an authoritative atomic snapshot without an independently verified revision/snapshot mechanism. Empty authorized container can be complete; absent DB connection is UNAVAILABLE. Errors remain fail-closed.

## Explicit size and privilege gates (R7 review remediation)
The endpoint rejects any row whose opaque `extra` exceeds 4,096 bytes, or any page whose aggregate base64 `extra` exceeds 65,536 characters. Rejection returns no partial rows, `complete=false`, and an `INCOMPLETE_*` status; the server does not truncate opaque bytes or declare success. With at most 100 fixed-shape rows and bounded extras, the response data is bounded; framework error outputs and headers are outside the row-contract budget. A count/page disagreement also returns INCOMPLETE. Offset pages across independent calls cannot be treated as one atomic complete snapshot.

**Required least-privilege grants:** SELECT on *both* `char_inventory` and `chars` for the dedicated loopback-only supervisor database principal. The second table is necessary to distinguish nonexistent characters from valid empty containers. This is a requirement, not a statement that the operator's deployed account already has these grants; verify and record the effective grants in local acceptance. A missing grant is a failed/unavailable observation, never proof that inventory is empty. Do not grant INSERT, UPDATE, DELETE, arbitrary SQL or unrestricted database administration.
