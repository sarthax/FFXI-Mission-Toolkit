# Canonical BDD Scenario Contract v2 — additive foundation proposal

**Status:** proposed, implementation guarded and read-only; no runner or editor adoption authorized. Parent [#1197](https://github.com/sarthax/FFXI-Mission-Toolkit/issues/1197), schema owner [#1259](https://github.com/sarthax/FFXI-Mission-Toolkit/issues/1259), domain drafts #1249–#1254, editor #1261 (Agent B), evidence #1262 (Agent D).

**Adoption compatibility supplement:** [SCENARIO_CONTRACT_V2_COMPATIBILITY_INTEGRATION.md](SCENARIO_CONTRACT_V2_COMPATIBILITY_INTEGRATION.md) covers the current-main independent audit, Agent E domain-by-domain mapping, Agent D identity/oracle diagnostics, editor UI treatment, exact source-fingerprint compatibility states, noncanonical gardening fixture and migration gates. `compatibility_report` now accepts an optional separately supplied `observed_sources={ref:{revision,sha256}}` map; this does **not** fetch/rehash files or authenticate the caller, and a structural match never authorizes execution.

## Audited baseline and compatibility contract

- `src/workbench/server_admin/feature_testing/test_specifications.py::validate_spec` requires outer `schema_version=1`, a fixed v1 assertion evaluator, and optional `purpose/rationale/behavior/steps/authoring`. The canonical catalog has exactly MOG-09 and INV-OBS-01. MOG-09 is the sole hard-coded verified runner. **Do not alter this allowance or change outer schema_version in the foundation.**
- `spec_drafts._validate_draft / save_draft` preserve canonical dictionaries and JSON, enforce unassigned + design_only, reject published overwrites. `scenario_authoring.editor_router.validate_editor_spec` and the JS guided model operate on the same v1 object. Metadata must not change accepted v1 drafts or suddenly grant them execution; the editor may need a later UI-only preservation review when editing populated v2 specs.
- `scenario_presentation.scenario_presentation` produces display-only UNKNOWN for unavailable observations and never establishes independent proof. Its existing paths should be identical for specs with no v2 metadata.
- `feature_testing.importer.validate_report`, `results`, `normalized_evidence` and `assertion_engine` are **not changed**: imported runner assertions are one source, not an independent normative oracle. Results pin DSP/headless/toolkit commits but do not require an immutable spec digest.
- Agent E staging files `data/testing/domain_drafts/{gardening,voidwalker,assault_nyzul,missions_quests}.json` (open PRs #1277/#1279/#1280/#1281) are **not valid canonical v1 specs**: extra observations, novel expression operations and guarded actions require an independently reviewed execution contract. Do not bulk-import, transform UNKNOWN into a boolean oracle, or rewrite those files. Domain review will map only source-backed metadata later.

## Additive namespace — `contract_v2`

The outer catalog and each entry remain `schema_version: 1`. A specification MAY include a separate optional `contract_v2` object. When present it MUST have exactly:

- `contract_version: 2` (explicit metadata contract version)
- `sources: []` — each `{ref, repository, path, line_start, line_end, revision, classification, sha256}`. `line_start/line_end` are both null or both positive, ordered integers. `revision` is a 40-character SHA or null; `sha256` is a 64-character content SHA-256 or null. Null means UNKNOWN, not trusted. `classification` is `dsp_source`, `client_dat`, `capture_observation`, `toolkit_code`, or `documentation`. `capture_observation` alone **cannot** be a normative oracle.
- `parameters: []` — each `{name,kind,identity,namespace,zone_id,binding_state,source_refs}`. Kinds: `item`, `key_item`, `npc`, `mob`, `zone`, `catalog`. `identity` is a bounded string or nonnegative integer or null. `namespace` is a bounded catalog name (or null if unresolved), `zone_id` an optional nonnegative integer. States: `unresolved`, `candidate`, `ambiguous`, `independently_source_verified`. The last is a **declaration only**, checked for revision+digest references but **not treated as an independent attestation**; external reviewer/source checks remain mandatory. For `npc`/`mob`, a declared verified binding must include zone scoping. Duplicate refs/names are invalid.
- `oracles: []` — each `{assertion_id,oracle_type,source_refs,confidence}`. `assertion_id` MUST exist in the unchanged v1 assertion list. `oracle_type` is `unknown`, `source_rule`, `source_literal`, or `reviewed_manual`. `confidence` is `unknown`, `candidate`, or `source_cited`. `source_cited` requires a pinned DSP source (revision+digest), but **does not authenticate the source, expected value or runtime observation**. `unknown` requires `confidence=unknown` and no source refs. The v1 `assertions[].expected` expression remains the evaluator's only existing contract; metadata cannot replace normative expected values.
- `step_requirements: []` — each `{step_id,capability,operation_class,required_permissions,required_readbacks,approval_required,execution_gate}`; `step_id` MUST match an authored v1 step. Capabilities: `unassigned`, `read_only_observation`, `server_readback_candidate`, `gm_diagnostic_candidate`, `client_action_candidate`, `gm_action_candidate`, `manual_checkpoint`. Operation classes: `unknown`, `read_only`, `mutating`. `required_permissions` is a bounded list drawn from `operator_approval`, `disposable_character`, `server_read_grant`, `client_control`, `gm_privilege`, `cleanup_verification`; `required_readbacks` are bounded *names*, **not registered endpoints**. `execution_gate` MUST be `blocked` (no `ready` or `approved` value). An action candidate cannot claim read-only; mutating requires operator/disposable/cleanup permissions and approval. An unknown GM diagnostic does not automatically get read-only classification. No component may use this section to dispatch.
- `fingerprints: {base_spec_sha256,dsp_commit,headless_commit,toolkit_commit}`. Values are strict SHA strings or null. `base_spec_sha256` hashes the canonical JSON of the whole v1 specification **excluding** `contract_v2` (UTF-8, keys sorted, compact separators, ensure_ascii=False), preventing recursive hashing. Engine commit IDs are compared to externally supplied runtime revisions only when available. A mismatch is BLOCKED; null/unavailable is UNKNOWN. **MATCH is structural compatibility, never run authorization.**

Limits: at most 20 sources, 30 parameters, 30 oracles and 100 step requirements; text, IDs, relative paths and reference membership are validated. All references are local to this metadata namespace or existing v1 IDs; arbitrary shell/SQL/packet capabilities are rejected.

## Migration

1. **Read:** absent `contract_v2` is fully valid legacy v1, not implicitly populated, not promoted to verified, and not reserialized with invented defaults. Unknown metadata versions are rejected rather than silently discarded.
2. **Validate:** invoke the v2 validator only if the optional metadata object exists. Keep prior v1 fields, expectation literals, steps, runner gates and evaluator semantics unchanged.
3. **Write:** serialize the entire validated dictionary without pruning optional fields; existing v1 object round-trips identical. `contract_v2` round-trips without conversion, and the draft store's 32KiB maximum remains. Avoid mass rewrite of `test_specifications.json`.
4. **Stage:** Agent E's domain drafts stay as separate staging artifacts. A reviewed mapper must explicitly convert unsupported observations/operations to permitted canonical states or leave them UNKNOWN; no auto-enabling, no numeric/zone ID guessing and no fake `equals UNKNOWN` assertion.
5. **Execute:** `contract_v2` has no runner semantics. Any future execution eligibility needs separate operator approval, capability permissions, trusted source resolution, matching installed binary and independent readback contract review in XIHeadless/Toolkit. UI display metadata cannot grant permissions.
6. **Imported runs:** keep historical recorded verdict, report fingerprint status separately from independent evidence status; don't rewrite old run records or assume `base_spec_sha256` matches current spec for historical imports.
7. **Ownership:** Agents B/D/E review the field names and migration plan before any UI, capture importer or domain-spec expansion. No UI/runner/catalog adapter changes in this PR.

## Acceptance to verify

Focused offline tests: legacy MOG-09/INV-OBS-01 identity/byte-for-byte no-extension behavior, optional metadata round-tripping, missing hashes and engine commits UNKNOWN, conflicting digests BLOCKED, unresolved/ambiguous bindings, fake source-verified claims without cryptographic pins rejected, prohibited SQL/shell/packet capability names, mutating without approval rejected, editor draft still design-only and viewer output invariant absent metadata.

**Could not verify here:** local DSP/client DAT source hashes, actual checked-out server binaries/revisions, Agent E domain runtime eligibility, independent oracle readback and client/server captures. These require a local operator and reviewed integration after contract acceptance.
